# Пункт 5 — интеграция с Ujin OS

Реализован мост между собственным интерфейсом, локальными эмуляторами и API Ujin.
Исполнение сценариев остаётся в FastAPI: для обмена устройствами сервис Autoscripts не требуется.

## Что работает в коде

- Фоновый HTTP-опрос команд, публикация состояний и событий из общей шины приложения.
- Привязки `локальный ID → serialnumber Ujin + ext_guid` в `data/ujin_bindings.json`.
  Серийные номера передаются строками, чтобы JavaScript не округлял большие числа.
- Два этапа инициализации новых сигналов, числовой JSON-транспорт, поле класса `c`, обход серверной потери нуля через `0.001`.
- Проверка доставки чтением `get-device-info`: ответ `error=0` сам по себе не считается подтверждением записи.
- Команды через тот же `DeviceManager`, что используют UI и сценарии. Входящие значения проверяются по декларации;
  read-only сигналы не исполняются как команды.
- Курсоры команд сохраняются после успешного исполнения и до подтверждения. Повторный task и старые timestamp не исполняются повторно.
- Повторные подключения с задержкой до 60 секунд, отдельные ошибки устройств, сохранение очереди событий на время сетевого сбоя в работающем процессе.
  Курсоры переживают перезапуск; очередь событий хранится в памяти, при запуске публикуется текущий снимок состояний.
- Панель **Ujin OS** в собственном интерфейсе: привязки, состояние обмена, ручная синхронизация, чтение карточки, отправка команды через платформу и журнал.
- LOCAL не требует сети. Автоматический обмен запускается только при `APP_MODE=live` и наличии доступов.

## Настройка вашей команды

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe backend\tools\configure_ujin.py --access-file "C:\\...\\доступы.json" --live
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Открыть **http://localhost:8000**, затем **Ujin OS** справа сверху.
Готовая сборка интерфейса обслуживается backend. Для разработки frontend по-прежнему запускается через `npm run dev` из `frontend`.

Настройщик создаёт привязки пяти уже выданных устройств квартиры 2791 и `backend/.env` со ссылкой на внешний файл доступов.
Пароли и токены не копируются в исходники и не передаются браузеру.
Вход сотрудника использует `app=employee`; токен на этом стенде находится в `data.user.token`.
Публикация и BMS-опрос используют сотрудника, команды квартиры — предоставленный токен жителя.
Альтернатива файлу доступов: переменные `UJIN_UST` или `UJIN_LOGIN/UJIN_PASSWORD`, `UJIN_APARTMENT_ID`, при необходимости `UJIN_CONTROL_UST`.

При первом запуске на чистой машине: установить зависимости `backend/requirements.txt` в `.venv` и выполнить `npm ci; npm run build` в `frontend`.

## Реальные ограничения стенда, обнаруженные 31.10.2026

Авторизация и чтение всех пяти выданных устройств проходят. Полноценная двусторонняя автоматизация на текущем стенде пока не подтверждена.

Публикация ряда сигналов (`leak`, `lamp`, `temperature` и других) возвращает `error=0`, `data.result=[null,...]`,
но эти показания отсутствуют в последующем чтении. Некоторые стандартные сигналы (`mode`, `online`, `voltage`) появляются.
Это наблюдение; по одному такому ответу нельзя установить, отсутствует ли словарь, ограничена ли его регистрация или скрыто ли значение в BMS.

Отдельно проверена команда `mode=1` своему термостату: платформа приняла запрос с токеном жителя,
но BMS-карточка не выдала task для исполнения. Исходный режим `mode=3` восстановлен запросом через платформу.
Успешный ответ команды означает приём запроса, а не подтверждение выполнения эмулятором.

Для завершения живой приёмки организаторам нужно проверить на **своих пяти устройствах**:

1. Соответствие выданных `ext_guid` фактическим идентификаторам и разрешение публикаций от сотрудника с `apartment_id=2791`.
2. Наличие словарей из `UJIN-REQUIRED-SIGNALS.json`, числовой тип сигналов и доступность значений в BMS.
3. `management=rw/w` для команд и выдачу `signal_task_value`/`task` с timestamp через `bmsdevice/get-device-info`.

Экспорт для администратора без секретов:

```powershell
.\.venv\Scripts\python.exe backend\tools\export_ujin_signals.py
```

Приложение отображает такие потери данных как ошибку интеграции. Локальные устройства и сценарии продолжают работать.
Административные обходы авторизации и изменение общих словарей платформы не используются.

## Проверка

```powershell
# Без изменения значений: проверить авторизацию и чтение карточек.
.\.venv\Scripts\python.exe backend\tools\check_ujin.py

# Публикует состояния эмуляторов и проверяет их чтением с Ujin.
.\.venv\Scripts\python.exe backend\tools\verify_ujin.py

# Дополнительно проверяет команду света и возвращает исходное состояние эмулятора.
.\.venv\Scripts\python.exe backend\tools\verify_ujin.py --command

# Офлайн-тесты (из backend).
..\.venv\Scripts\python.exe -m pytest tests -q
```

Живая проверка записывает `UJIN-LIVE-CHECK.json` без секретов и возвращает код 1, если обмен не подтверждён.
Тесты изолированы от реальных доступов, даже если `.env` включает LIVE.

## Контракты

Использованы предоставленные `api-methods.md`, `PULL-CLIENT.md`, `protocol-porting.md`, starter-pack клиент и файл доступов команды.
База нормализуется: допускается адрес как с `/api`, так и без него.

| Направление | Интерфейс |
|---|---|
| Вход сотрудника | `POST /api/auth/authenticate/`, form `login,password,app` |
| Чтение и task | `GET /api/bmsdevice/get-device-info/`, `token,serialnumber,mts=1` |
| Публикация | `POST /api/import_device/group-update-device-signal/`, JSON `{data:[{sn,s,v,c}]}` |
| Авторизация публикаций UAE | Query `token,apartment_id,serialnumber`; в строках `sn` — внешний ID |
| Команда из интерфейса через Ujin | `GET /api/apartment/send-signal/`, токен жителя и короткое имя сигнала |

REST нашего приложения: `/api/live/status`, `/bindings`, `/bindings/{device_id}` (PUT/DELETE), `/sync` (POST), `/devices/{serial}`,
`/devices/{serial}/command`. Статус и журнал также идут через `/ws/events`.
При экспорте простого сценария в Autoscripts используются реальные serialnumber из привязок; условия и несколько действий,
которые нельзя выразить этим контрактом, отклоняются с объяснением. Экспорт сохраняет сценарий; включение на платформе выполняется отдельно.
